# 银企直连实时出款通道对接说明书（V3.4）

编制部门：资金清结算研发组；经办：韩磊；复核：宋洋；更新日期：2026年10月28日。

## 一、通道概况与接入模块

`gateway-router` 负责统一转发内部各业务线对外部合作方的 HTTP 调用，底层共用 `src/http/client.py` 中的 `request()` 封装。当前接入该封装的上游服务分为两类：

| 业务模块 | 源码位置 | HTTP 方法与路径 | 接口性质 |
| --- | --- | --- | --- |
| 商品目录查询 | `src/services/catalog_client.py` | `GET /v1/catalog/items` | 只读查询（幂等） |
| 实时报价查询 | `src/services/pricing_client.py` | `GET /v1/pricing/quotes/{sku}` | 只读查询（幂等） |
| 银企直连代付 | `src/services/wallet_payout.py` | `POST /v1/bank/transfer` | 资金实时出款（非幂等） |

## 二、实时出款接口超时处理约定

1. 合作银行当前生产版本（V3.4）的 `POST /v1/bank/transfer` 接口采用无状态报文直连，**不支持同步幂等键（Idempotency-Key）去重**。银行核心每收到一次合法的 `POST /v1/bank/transfer` 请求，均会生成一笔新的独立划款流水并即时扣减备付金账户。
2. 当网关与银行专线之间偶发链路抖动返回 HTTP `504 Gateway Timeout` 时，仅代表我方未在超时窗口内读到银行回执，银行核心侧可能已经受理并完成出款。
3. 按银行对账协议，代付请求遇到 504 超时后应将订单置为“待查单”状态，由异步对账任务调用 `GET /v1/bank/transfer/status` 确认银行侧最终结果后再决定是否补发；不得在 HTTP 客户端层对 `POST /v1/bank/transfer` 自动重发。

## 三、只读查询接口容错说明

目录与报价两类 `GET` 只读接口不产生任何资金或状态副作用，可在遇到上游 504 超时时启用有限次数（如 3 次）的自动重试，以平滑偶发抖动。
