# 售后退款派发服务

项目负责将已审批退款交给支付渠道，供客服工作台显示处理进度。订单扣款、退款审批、渠道受理和财务到账核对分开保存。这里的渠道适配器只运行本地合成交易，不访问网络或真实支付账户。

## 调用与结果

入口为 `refunds.dispatch(request)`，request 包含 `refund_id`、`payment_id`、`amount_minor`。金额以分计，refund_id 是本公司为该笔售后生成的商户退款号，payment_id 是原支付号。返回 state、refund_id 及渠道受理结果；pending 表示仍需查渠道，不表示退款已被拒绝。

渠道入口为 `channel.submit_refund(refund_id, payment_id, amount_minor)`。相同商户退款号用于查得或重取同一笔受理结果；更换号码是另一笔退款请求。遇到 TimeoutError，调用者只知道回执没有按时到达。出款是否发生需按退款号核渠道记录。

## 业务流转

客服先核售后审批与退款金额，派发服务提交申请；渠道返回受理后，财务仍按日结回单核对。客服不能把请求超时手动填成付款失败，也不能通过改申请金额完成对账。已拒绝、待查询和已受理分别进入工作台三类队列。

`docs/`保留当班接入和客服记录，`data/`为审批清单与历史渠道摘录。维护时保留 dispatch 的入口及金额单位，记录实际返回状态。修改项目代码后需在本地适配器上核正常受理、回执超时及明确拒绝，调试结果不要写成真实资金回单。
