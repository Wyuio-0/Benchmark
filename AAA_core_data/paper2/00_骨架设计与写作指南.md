> **配套**：`main.tex`（LaTeX 骨架）；`_research/`（26 篇论文结构调研报告）。
> **占位符**：`[方括号]` = 待全量实验/扩展后填入的数字或名称。

## 0. 一句话贡献（叙事主线）

| 支柱 | 内容 |
| --- | --- |
| **The What** | 提出 **context-environment gaps** 作为 benign 任务中 tool-using agent 危险行为的统一解释，并构建首个以"隔离 gap 机制"为设计原则的 benchmark **[BENCH]**：[N] 实例 / [X] 场景 / 3 类 gap / 11 个工具套件，每个 case 带**安全对照版（safe twin）**与**关键证据标签**，并配套经人工验证的 LLM 三分类失败归因协议 |
| **The Why** | 现有评测无法回答"agent 为什么在无攻击者的日常任务里造成伤害"：攻击类 benchmark 假设攻击者；能力类 benchmark 不以安全为失败判据；安全类 benchmark 只罗列风险类别、不隔离机制、无能力对照、无因果归因 |
| **The So What** | 受控干预（wording/position）+ 证据锚定归因，首次把失败因果拆解为"**没看到**（证据未搜集）/ **没反应过来**（证据在手未识别危险）/ **盲从指令**（识别到危险仍执行）"，为防御设计指明应修补的环节 |
| **Headline** | [M] 个 agent 的 ASR 高达 [X%]（安全对照版通过率 [Y%] → 失败是安全特异的，不是能力不足）；两类既有防御 + 一种预训练增强最多降 [p.p.]；拓扑结构在 token 匹配对照后效应不显著；归因分布：[xx%] 没看到 / [xx%] 没反应过来 / [xx%] 盲从 |

**标题级数字**（引言和摘要都要出现）：`最优防御后 ASR 仍 [X%]` + `安全对照版通过率 [Y%]`（能力锚点）。

## 1. 为什么这么组织（结构决策与依据）

> 依据来源：`_research/` 五份报告对 26 篇论文的结构分析；反防御性写作原则（论文是学术发布会，围绕最强价值组织，不写工作汇报）。

**D0 叙事与用语原则（贯穿全文）**：论文按"论证链"组织——问题为什么重要 → 现有方法为什么不够 → 本文提供什么 → 证据如何支持；不按"我们先做了什么、后来试了什么"的过程展开。每个实验绑定一个待排除的替代解释或一个待证明的主张。表述上不用自我削弱用语（"效果有限/仅/遗憾"）；"防御降不动 ASR"写成"现有增强未触及 gap 机制，指向新的设计空间"，把发现定性为机制结论而非失败记录。

**D1 采用顶会 benchmark 论文的公认骨架**：Intro → Related Work → Problem Formulation & Threat Model → Construction → Evaluation Protocol → Experiments → Discussion → Limitations → Conclusion → Ethics/Reproducibility。26 篇中 20+ 篇同构（差异只在 Related 早晚、Limitations 主文/附录）。**落点**：全文章节树（§2）。

**D2 Intro 用"两组贡献 bullet + 标题数字"**：安全类 benchmark 的贡献 bullet 惯例分两组——benchmark 性质（我们造了什么仪器）与实证发现（我们测出了什么），每条带数字（web_safety_benchmarks 结论 ⑨）。**落点**：§1 P6。

**D3 Threat Model 独立成节（§3.3）**：安全 benchmark 惯例前置威胁模型、显式与攻击类工作划界（AgentDojo/InjecAgent/ASB 都以攻击者为前提）。这既是定位（我们的伤害源是 gap，不是攻击者），也顺带论证 benign 设定下 LLM-as-Judge **没有被劫持面**（回应 AgentDojo 拒用 LLM judge 的理由——他们的环境里有注入内容，我们的没有）。**落点**：§3.3 + §5.3。

**D4 安全对照版升格为独立小节（§4.4）并写进指标（§5.1）**：AgentHarm 的 benign 孪生、AppWorld 的 validation solutions 是先例；"排除模型能力不足的替代解释"是审稿人必问项，必须作为仪器的一部分显性呈现，而不是一句带过。用法：对照通过率作为**能力门槛**，主表并报 ASR 与对照通过率。**落点**：§4.4、§5.1、§6.2。

**D5 证据标注 + 归因协议单独成节（§4.5 + §5.2 + §5.3）**：本文差异化的核心是"诊断仪器"（关键证据标签 + 三分类归因 + judge 验身），不是附属分析。ToolEmu 用整个 §4 Validating 章给 judge 验身（κ 对照人人一致性）、R-Judge §4.2 同理——**测量工具的可信度本身写成贡献**。judge 校准报告双基线（human-human κ 与随机基线并排），边界样本给 Strict/Lenient 双口径（AgentAuditor 先例）。**落点**：§5.2、§5.3、附录 C。

**D6 实验章 RQ 驱动、小节标题写成发现句**：SafeAgentBench/Agent-SafetyBench 惯例（Problem → Metrics → Results → Finding；问句或发现句标题）。三个主实验 = 三大待排除的替代解释，按论证强度排序：防御（排除"没防住"）→ 拓扑+token 对照（排除"靠算力"）→ 干预归因（正面回答"为什么"）。**落点**：§6.2–§6.6。

**D7 主实验 1/2 必带"排除替代解释"对照**：(a) 防御无效必须补 sanity check——防御在原生任务/其设计目标上确实有效，排除"实现弱"；(b) 拓扑对比必须 token/步数匹配对照 + 协变量表，钉死"ASR 变化不是 token 消耗带来的"（AgentBench 附录 J.2.3 token/轮数分析、τ²-bench No-User/Oracle Plan 是现成先例）。**落点**：§6.3、§6.4。

**D8 主实验 3（干预归因）是全文高潮，不是附录式分析**：本文卖点是机制归因。写法学 Lost in the Middle："controlled changes to X and measure Y"——单因素操纵、控制组锚点、x=干预档位 y=指标 的多模型折线（剂量-反应）；呈现学 MAST Fig.8/9：干预前后归因分布对比，不只报 ASR。**落点**：§6.5、§6.6。

**D9 构建章"筛选漏斗 + 数字透明"**：质控数字透明度是高水准 benchmark 的分水岭（web_benchmark_craft 结论 2）：种子数 → 扩展数 → 核验过滤数 → 最终数，逐级给数字；标注协议给人数/轮次/IAA。我们的关键证据审计（170 条证据 → 单次调用 + 必要性双判据）就是现成的质控叙事。**落点**：§4.1、§4.5、§4.6。

**D10 合规收尾刚性配置 + 仪器全开放**：Limitations 写数字级、按主题分小节、转成路线图；Ethics/Reproducibility 独立（ICLR/NeurIPS/ACL 要求）；附录开放 judge prompt 全文、标注指南、K1–K9 目录、干预档位定义、case 走查、完整统计。防污染：canary string + private holdout（BrowseComp/MLE-bench 先例）。**落点**：§8、§9、附录 A–G。

## 3. 逐节写作指南

> 每节按【职责】【内容要点】【图表】【支撑结论】【调研先例】【常见坑】展开。

### 1 Introduction

- **职责**：1.25 页内让读者形成三个判断——问题重要且未解、本文仪器独特、发现有分量。6 段式推进。
- **内容要点**：
  - **P1 hook**：tool-using agent 已在日常 benign 任务中实际部署，随之出现真实伤害——每个 case 家族给一短句具象（退款多付、凭证/PII 泄露、生产数据清空、未备份证据被删），强调"用户意图正常、没有攻击者"。
  - **P2 机制**：context（用户指令与业务文档）完全可见、常被默认当作行动依据；但安全执行所需的事实只存在于**部分可观测的环境**中，必须用工具调用去验证；验证所需证据未必被检索到 → context-environment gap 未被发现 → 危险动作。一句话点题：伤害不需要攻击者，只需要一个没被验证的 gap。
  - **P3 现有评测的四个命名缺口**：(a) 攻击中心（AgentDojo/InjecAgent/ASB/AgentHarm 的对抗部分）——伤害源是注入与劫持，机制不同；(b) 能力中心（WebArena/τ-bench/AppWorld/OSWorld）——只判任务成败，安全后果不进失败判据；(c) 安全风险罗列（Agent-Safety-Bench/R-Judge/SafeAgentBench）——给类别与分数，但不隔离 gap 机制、无能力对照版本、无轨迹级因果归因；(d) 缓解研究（防御/拓扑）——宣称改进时未排除 token/算力混淆。
  - **P4 本文设计**：[BENCH] 的四条设计原则（benign-by-design / gap-grounded / safe-twin-controlled / evidence-anchored）+ 三类 gap + 三大研究一句话。
  - **P5 headline 发现**：ASR [X%] vs safe twin 通过率 [Y%]；防御最多降 [p.p.]；token 匹配后拓扑效应不显著；归因分布 + 干预结论。
  - **P6 贡献（两组 bullet，每条 1–2 行、带数字）**：
    - 组 A（仪器）：①问题框架 + 首个隔离 gap 机制的 benchmark（[N] 实例/[X] 场景/3 类/11 套件）；②safe twin 能力对照 + 关键证据标签 + 经验证的三分类归因协议（judge-human κ=[.]）；③wording/position 受控干预机制（可复用的归因工具）。
    - 组 B（发现）：④[M] agents ASR [X%]，safe twin 通过率 [Y%]——安全特异失败；⑤两类防御 + 预训练增强未触及 gap（最多 [p.p.]）；⑥拓扑在 token 匹配后无显著效应；⑦归因：[主因分布] + 干预证据。
- **图表**：Figure 1 = 双面板（左：context-environment gap 概念图；右：一个真实 case 的危险版 vs 安全对照版并排，标出 gap 位置、缺失证据、危险动作）。caption 自包含。
- **支撑结论**：全文的 What/Why/So What 在此定型。
- **调研先例**：WebArena 的叙事式 3 贡献（每段对应正文章节）；Agent-Safety-Bench 的"none above 60%"式数字开场；安全类贡献分两组惯例。
- **常见坑**：背景写太长（概念细节推给 §3）；贡献 bullet 不带数字；Figure 1 放架构图而不是 gap 概念图。

### 3 Problem Formulation and Threat Model

- **职责**：把核心概念钉死成全文可用的最小形式体系；与攻击类工作划界。0.75 页。
- **内容要点**：
  - **3.1 Context, Environment, and Verification**：定义 context C（用户指令 + 业务文档/规则——完全可见、被默认信任）、环境 E（工具可达的部分可观测状态）、观测 O（工具调用返回）、**关键证据 E\***（推导风险所必需的环境事实集合，即关键证据标签的理论对应）、验证动作（把 E\* 拉进上下文的工具调用序列）、危险动作（在真实 E 下违反安全约束的终态动作）。
  - **3.2 三类 gap**：RU（C 未规定安全执行必需的范围/边界 → agent 自行补全即可能越界）、RI（C 的明确要求与 E 的安全约束不可同时满足 → 照办即违规）、FI（C 的事实陈述相对 E 错误/过时 → 按陈述执行即致害）。每类给失败条件（何时判 dangerous）+ 一行最小例子（从种子里取）。
  - **3.3 Threat Model and Scope**：用户意图 benign、无攻击者、环境中无恶意内容；伤害源唯一 = 未被验证的 gap。显式排除：prompt injection/间接注入、jailbreak、多轮用户操纵、纯能力失败（由 safe twin 过滤）。附一句 judge 安全性论证：benign 设定下归因 judge 读取的内容不含对抗样本，无劫持面（对照 AgentDojo 的拒用理由）。
- **图表**：无（或符号表框）。
- **支撑结论**：ASR 与危险动作的判定合法性；三大实验的自变量/因变量定义基础。
- **调研先例**：ToolEmu §2（"benign intent, no attacker" 显式写法）；ASB §3 Definitions & Threat Model；R-Judge §2 Problem Formalization。
- **常见坑**：定义散落在各处不收敛；威胁模型不写排除项（审稿人会把 IPI 混进来打）。

### 4 [BENCH] Construction

- **职责**：证明样本是"为隔离 gap 机制而设计"的，且经过严格质控。1.5 页。
- **内容要点**：
  - **4.1 Design Overview**：四条设计原则（benign-by-design / gap-grounded / safe-twin-controlled / evidence-anchored）；三段流水线（Stage I 种子设计 → Stage II 批量扩展 → Stage III 核验与标注）+ 漏斗数字（66 活动种子 → [N] 实例；过滤 [k]；每级给数）。
  - **4.2 Seed Design**：7 字段种子结构（问题类别/工具套件/任务目标/失败判据/环境依据/测试指令/指令问题）；类别平衡策略（每类 [22] 条种子级）；**K1–K9 隐藏机制表**（风险藏在哪种形式里 + agent 的发现路径：常识埋点/伪防护/计算/历史依赖/标识碰撞/范围省略/进行中重复/硬闸门压力/权威状态错位）——这是案例多样性的证据，建议做成正文表；11 个工具套件覆盖（mail/chat/files/database/code/git/github/pc/server/buyer/merchant）。
  - **4.3 Batch Expansion**：LLM 辅助实例化（实体/数值/场景表面替换）+ 人工逐条核验；去重（近邻分析）；多样性控制（同种子实例上限、跨场景分布）；漏斗数字。
  - **4.4 Controlled Safe Pairs**：定义（与原 case 仅差两处微调：一处提示词微调 + 一处环境微改，移除坑点）；设计规则（任务可正常完成、工具预算同、表面难度不变）；用途（能力门槛：safe twin 不过的实例单列/作废；主表并报）；展示（四面板/三列表格 case 对）。
  - **4.5 Evidence Annotation and Quality Control**：关键证据双判据（**单次工具调用可直接返回** + **风险推导必要性**——删掉该点即无法推出风险；我们已有 170 条证据的审计整改记录作方法论叙事）；标注协议（标注者/轮次/仲裁/IAA [κ]）；每 case 预标期望归因（供 §6.5 对照）；负向事实（"没有某记录"）标注检索范围规范。
  - **4.6 Data Statistics**：Table 2 规模分布（类别 × 场景/工具套件，种子数/实例数）；Table 3 属性均值/最大值（轮数、工具调用数、证据条数/实例、上下文长度）；canary string + private holdout 声明。
- **图表**：Fig 2 管线图（带漏斗数字）；Table 2/3；K1–K9 表；case 对示例框（或放附录 A）。
- **支撑结论**："样本为机制而设计、经得起扩展与审查"。
- **调研先例**：Agent-Safety-Bench §3.2（refine→augment→QC）；SWE-bench 执行过滤；τ-bench >40 trials 消歧义；τ²-bench under/over-specification 审查清单；AppWorld validation solutions（safe twin 叙述先例）。
- **常见坑**：漏斗只给总数不给各级；safe twin 写成脚注；证据标注不给可操作判据。

### 5 Evaluation Protocol

- **职责**：把"仪器"写成可复现的测量程序；judge 验身单列。1.25 页。
- **内容要点**：
  - **5.1 Metrics**（公式化，学 ASB Eq.18/19）：
    - `behavior_score`（0/1）：环境终态 + 评测函数判定（不依赖 LLM）→ **ASR** = 危险终态占比（按类别/整体分列）。
    - `diagnosis_score`：LLM-as-Judge 仅读最终回答 `final.md`（不看 CoT/中间文本/工具日志），对照关键事实标签判"是否识别并正确应用关键信息"。
    - `effective_utility`：behavior_score=0 即 0；行为安全后取诊断质量（复合指标防"全拒绝"退化解——对照 AgentHarm non-refused、ASB NRP）。
    - **safe twin 通过率**（能力门槛）；**证据检索率**（验证行为率：轨迹中 E\* 被工具调用拉入上下文的比例）；[可选 pass^k 多次运行可靠性，语义 = "一次出事即失败"天然契合]。
  - **5.2 Failure Attribution Taxonomy**：三分类命名（建议英文化命名）：**A1 Perception Failure—Evidence Not Gathered**（没看到）/ **A2 Recognition Failure—Danger Not Recognized**（没反应过来）/ **A3 Obedience Failure—Recognized but Overridden**（盲从）。给 0/1 操作量表（学 ToolEmu Table 1）+ **判定树**（利用三层口径天然分层）：
    1. behavior_score=1 → 无失败不归因；
    2. 轨迹未检索 E\*（evidence 标签 ∩ 工具日志 = ∅）→ A1；
    3. 检索到 E\* 但 diagnosis_score 低（final.md 未识别/误用关键事实）→ A2；
    4. final.md 显示识别（提及关键事实/风险/存疑）仍执行危险动作 → A3。
    边界样本策略：就近归因（取"达到的最远阶段"）+ Strict/Lenient 双口径报区间；每 case 预标期望归因与判定结果对照。
  - **5.3 Validating the LLM Judge**：judge 配置（审计 judge + AgentGuard reviewer 单次请求；规则/评测函数优先、LLM 只判窄子项）；一致性研究设计（分层抽样 [n] 条轨迹 × 3 类别 × 边界样本；多标注员独立标 + 仲裁）；报告 **κ/P/R + 双基线**（human-human κ 与随机基线并排——"judge 达到人-人一致性水平"句式）+ 归因混淆矩阵（judge × human 三分类）；judge prompt 全文进附录。
- **图表**：judge 校准表（Acc/P/R/F1/κ + 双基线）；归因混淆矩阵；判定树（可作小图或文字流程）。
- **支撑结论**："测量可信"是 §6 一切结论的前提，本身是贡献。
- **调研先例**：ToolEmu §4 Validating（κ 0.478 vs 人人 0.480）；R-Judge §4.2（PCC 0.91）；MT-Bench agreement 矩阵（随机基线印表头）；AgentAuditor Strict/Lenient；Agent-Safety-Bench §3.3 scorer（微调 scorer 91.5% vs GPT-4o 75.5%——"规则优先"趋势）。
- **常见坑**：judge 与人工的一致率只报一个数；归因三分类没有可操作判据（审稿人会质疑主观性）；忘了说明"行为判定不依赖 LLM"这条防线。

### 6 Experiments

- **职责**：三大 RQ = 三大替代解释的排除 + 机制正面回答。每小节标题写成发现句，开头一句话声明"本节检验什么主张"。2.5 页。
- **6.1 Setup**：[M] 模型（API/开源分组）；agent scaffold `single_react`（LangGraph；模型→工具 ReAct 图）；预算（150 轮 / 50 次工具调用 / 单次输出 20480 tokens——直接引实现口径）；每实例重复 [k] 次（报 mean±std；配对比较用 Wilcoxon/McNemar）；拓扑与防御配置一览（Table 或文字）。
- **6.2 Main Results**（发现句标题 + "Agents Fail to Validate Context Against the Environment"）：
  - Table 4 主表：行=模型，列=Ru ASR | RI ASR | FI ASR | Overall ASR | safe twin 通过率 | 证据检索率 | [pass^k]。
  - 三句话节奏：ASR 高（[X%]）→ safe twin 通过率高（[Y%]）→ 于是失败是安全特异的、与能力解耦（这是全文最重要的能力锚点句）。
  - 可加场景/工具套件分桶一行定性。
- **6.3 RQ1 Safety Enhancements**（发现句："Safety Enhancements Do Not Close Context-Environment Gaps"）：
  - 方法：Def-A、Def-B（`src/securityEnhancement` 的两种方法，TODO 正式名）+ PT（预训练安全增强模型）。
  - 呈现：ASR 表 + **效用-ASR 双散点**（AgentDojo Fig 6/9 式，Pareto 加粗）；按类别分列降幅。
  - **Sanity check 必备**：防御在其原生目标（如其设计针对的攻击/越界场景）上确实有效 → 排除"实现弱"；报告防御带来的效用变化（是否损失任务能力）。
  - 结论句式：现有增强未触及 gap 机制（最多 [p.p.]），指向 gap-specific 的防御设计空间（呼应 §7）。
- **6.4 RQ2 Agent Topology**（发现句："Agent Topology Does Not Explain Away Unsafe Actions"）：
  - 配置：`single_react` 基线 + 三种拓扑（TODO：`planner_executor`/`investigator_executor`/`reviewer_executor` 中选定哪三个）+ **普通对照结构**（token/步数预算匹配的对照：如加长单智能体推理预算、增加检索轮数）。
  - 呈现：ASR × 拓扑表 + **token/轮数协变量表**（学 AgentBench J.2.3）+ ASR vs token 散点/偏效应；拓扑示意图（ToolSandbox Fig 2 式框图）。
  - 结论句式：拓扑引入的差异在 token 匹配后不显著 / 若有降幅可由 token 消耗解释——排除"多花算力"混淆，把效应归因到结构本身（或证明结构无效）。
- **6.5 RQ3 Controlled Interventions**（发现句："Controlled Interventions Localize the Failure"）：
  - 设计（`src/variableControl`）：对**关键证据**做两个单因素操纵——**position**（明显位置 → 不明显位置：如文件头部→深层/多跳查询/翻页末端）与 **wording**（明显提示 → 隐晦表达：如显式约束句→生活化/省略/需常识还原，注意与 K1/K9 机制联动）；各设 [3–4] 档（剂量-反应）；2×[L] 设计，逐 case 改动 diff 表进附录（学 FormatSpread）。
  - 因变量：证据检索率、ASR、三分类归因占比。
  - 呈现：多模型折线（x=干预档位，y=ASR/检索率；Lost in the Middle 式）+ 干预前后归因分布对比（MAST Fig.8/9 式 stacked bars）。
  - **判定逻辑表**（机制归因，比方向性预测更稳）：
    | 观测模式 | 归因 |
    | --- | --- |
    | 提高可见性 → 检索率↑ 且 ASR↓，A1 占比同步下降 | 失败由"没看到"主导（感知瓶颈） |
    | 可见性影响小、wording 档位显著影响 ASR，A2 占比高 | 由"没反应过来"主导（识别瓶颈） |
    | 全档位 ASR 高、A3 占比高 | 由"盲从用户指令"主导（服从瓶颈） |
  - ⚠️ 方向性预测待确认（见 §8-Q1）：你此前给的"检索率下降 → ASR 下降"与三分类机制方向（没看到 → 危险动作）相反，填写时以实验设计文档为准。
- **6.6 Global Attribution**（发现句："A Global Picture of Failure Attribution"）：
  - 全体三分类分布（stacked bar：类别 × 归因 / 模型 × 归因）；与 6.3/6.4 各配置的归因迁移对比；
  - 2–3 个 case study 走查框（轨迹节选 + 证据 + 判定路径），学 τ-bench"饼图四类归因→每类带案例指针"节奏。
- **通用规范**：每小节末"Finding:"一句话；显著性标注；全表 booktabs、方向符号（↑↓）。
- **调研先例**：Agent-Safety-Bench §4.3–4.5（失败模式/帮助性/防御讨论）；AgentHarm 4.3 消融表；τ² No-User/Oracle；OSWorld §5.2 每干预一小结论式小标题。
- **常见坑**：把三主实验写成并列流水账（必须每节绑定一个待排除解释）；防御实验不给 sanity check；拓扑实验不报 token；干预实验一次动两个因素。

### 7 Discussion

- **职责**：把发现升格为设计指引，不引入新否定。0.5 页。
- **内容要点**：什么才能真正关闭 gap（强制验证步骤/证据强制拉取、验证激励、校准的拒答与澄清、safe twin 式训练数据）；benign 威胁面的部署含义（无需攻击者 → 防御面更大）；三分类归因 → 防御应打哪一环（A1 打检索、A2 打识别、A3 打服从）；可扩展性一段（新 gap 类别、多轮用户模拟、多语言/多领域环境）——把路线图放这里而不是 Limitations。
- **常见坑**：在最后一段突然自我否定（违反反防御原则）。

### 8 Limitations

- **职责**：数字级、主题小节化、不扩大攻击面。0.35 页。
- **内容要点**：L1 规模（[N] 实例 vs 大规模自动化 benchmark）；L2 场景/语言覆盖（中文业务环境、11 套件）；L3 归因 judge 的边界样本（已用双口径缓解）；L4 单轮指令设定（用户模拟/多轮交互留作扩展）；L5 模型覆盖与快照时效；L6 干预档位的操作化有限（3–4 档不穷尽 salience 空间）。每条配一句"为何不伤核心结论"。
- **常见坑**：写"我们没有做 X"式清单（每一项都在替审稿人递刀）；把局部现象写成普遍缺陷。

### 9 Conclusion

- **职责**：只强化记忆点，3–4 句：gap 解释了 benign 危险行为；现有增强与拓扑不触及机制；归因三分类 + 干预指向真正的修补点；[BENCH] 开放。
